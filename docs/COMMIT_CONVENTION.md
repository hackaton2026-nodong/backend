# 커밋 컨벤션

모든 레포는 같은 커밋 규칙을 사용합니다. 프론트엔드, 백엔드, AI 레포가 분리되어 있으므로 작업 단위와 커밋도 레포별로 분리합니다.

## 기본 형식

```text
타입: 한국어 요약
```

예시:

```text
feat: 근로자 계약서 단계 전환 추가
fix: 상담 기록 선택 시 이전 대화 복원
```

## 허용 타입

| 타입 | 용도 |
| --- | --- |
| `feat` | 기능 추가 또는 사용자 플로우 추가 |
| `fix` | 버그 수정 또는 요구사항 불일치 수정 |
| `docs` | 문서 추가/수정 |
| `style` | 포맷, CSS, UI 표현만 변경 |
| `refactor` | 동작 변경 없는 구조 개선 |
| `test` | 테스트 추가/수정 |
| `chore` | 빌드, 설정, 패키지, 기타 관리 작업 |
| `build` | 빌드 시스템 또는 의존성 변경 |
| `ci` | CI 설정 변경 |
| `perf` | 성능 개선 |
| `revert` | 이전 커밋 되돌림 |

## 규칙

- 커밋 제목은 반드시 한국어를 포함합니다.
- 제목은 가능하면 72자 이내로 작성합니다.
- 한 커밋에는 하나의 의도만 담습니다.
- 프론트, 백엔드, AI 변경은 서로 다른 레포에서 따로 커밋합니다.
- API 계약, DB 계약, 화면 플로우 변경은 관련 문서를 함께 갱신합니다.
- push 전에는 레포별 검증 명령을 실행합니다.

## 권장 커밋 단위

- `feat`: 새 화면, 새 API 어댑터, 새 도메인 흐름
- `fix`: 리뷰 finding 하나 또는 긴밀히 연결된 finding 묶음
- `docs`: 합의 내용, API handoff, 실행 방법
- `chore`: 훅, 템플릿, 패키지 설정

## 로컬 설정

이 레포는 `.githooks/commit-msg`로 커밋 제목 형식을 검사합니다. 훅이 동작하도록 아래 설정을 유지합니다.

```bash
git config core.hooksPath .githooks
```

커밋 메시지 템플릿을 사용하려면 아래 설정을 적용합니다.

```bash
git config commit.template .gitmessage
```
