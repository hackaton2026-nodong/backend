1. 기본 방향
기존 서비스의 문제의식은 그대로 유지한다. 외국인 근로자와 고용주 모두가 노동 정보와 문서 해석에서 어려움을 겪
고 있고, 이를 해결하기 위해 계약서·임금명세서 분석, 다국어 상담, 공식 체크리스트, 대시보드, 기관·교육 연계가 필
요한 구조라는 점은 변하지 않는다.
따라서 올해 고도화의 핵심은 서비스 목적을 바꾸는 것이 아니라, 기존 기능들이 서로 따로 노는 느낌을 줄이고 하나의 
흐름으로 움직이게 만드는 것이다. 사용자가 메뉴를 찾아가며 기능을 순서 없이 쓰는 방식에서, 현재 상태를 기준으로 
필요한 기능이 자연스럽게 이어지도록 구조를 바꾼다.

2. 작년 대비 올해 구조 변화
작년 안에서는 기능의 종류가 이미 충분히 정의되어 있었다. 다만 사용 흐름의 중심이 질문형 챗봇에 상대적으로 가까
웠고, 문서 분석과 체크리스트, 대시보드, 기관 연계가 병렬 기능처럼 보일 위험이 있었다. 올해는 같은 기능을 유지하
되, 문서 분석과 상태 관리가 중심이 되고 상담은 케이스 코파일럿 역할로 이동한다.

3. 제안 아키텍처
3-1. 전체 흐름
전체 흐름은 온보딩 → Agent Center → 문서 분석 → 체크리스트 → 조치/연계 구조로 잡는다. 기존 기능을 줄이는 
것이 아니라, 사용자가 무엇을 먼저 해야 하는지 알 수 없었던 문제를 해결하는 방향이다.

3-2. OCR 및 문서 이해 레이어
문서 입력 단계에서는 PaddleOCR / PP-Structure 계열을 사용해 텍스트만 뽑아내는 것이 아니라 문서 레이아웃, 
표, 제목, 핵심 필드 위치를 함께 다루는 구조로 설계한다. 여기서 중요한 포인트는 OCR 결과를 그대로 LLM에 넣지 않
는다는 점이다.
• OCR 결과는 줄바꿈 깨짐, 표 손상, 숫자/단위 혼합, 언어 혼재가 발생할 수 있으므로 중간 정규화 레이어가 반드시 필요
• 문서 유형 분류(근로계약서/임금명세서/기타), 필드 추출, 날짜·금액·시간 정규화, 민감정보 마스킹, 근거 좌표와 
confidence 저장까지 선행
• 이 단계가 있어야 이후 Graph 기반 관계 매핑, 체크리스트 연결, 역할별 설명 분기, 대시보드 상태화가 가능
• 보안 설명은 'PaddleOCR 라서 자동으로 안전하다'가 아니라 '자체 배포·내부망 처리 구조를 택할 수 있어 원문 외부 전송
을 줄이기 좋다'는 식으로 정리

3-4. Agent Orchestrator
이 프로젝트에서 에이전트는 완전 자율 시스템이 아니라 '현재 상태를 보고 필요한 기능을 호출하는 오케스트레이

• 문서 리뷰 에이전트: 업로드된 문서를 OCR/정규화/분석으로 연결
• 체크리스트 가이드 에이전트: 공식 체크리스트와 현재 문서 상태의 연결 설명

• 기관/교육 매칭 에이전트: 지역·언어·주제·현재 위험 항목을 기준으로 추천
• 모니터링 에이전트: 만료 예정, 미업로드, 미완료 항목, 반복 위험 징후 알림

4. 근로자·고용주 분리 운영 상세 방안
이 부분은 작년 설명에서 상대적으로 약했던 지점이다. 서비스 대상은 처음부터 양측이었지만, 실제 화면·권한·공유 
정보가 어떻게 나뉘는지까지 명확히 제시할 필요가 있다. 가장 자연스러운 구조는 '하나의 플랫폼 + 하나의 공유 케이
스 + 역할별 뷰'다.
도식 4. 하나의 플랫폼 안에서의 역할 분리 구조
4-1. 기본 원칙
• 공유해야 하는 것은 공유한다: 같은 계약서, 같은 임금명세서, 같은 체크리스트 상태, 같은 교육/기관 추천은 공유 케이스
에 저장
• 해석과 행동은 역할별로 다르게 제공한다: 고용주에게는 조치·준법 중심, 근로자에게는 이해·권리 중심
• 민감하고 사적인 정보는 분리한다: 고용주 내부 작업 메모와 근로자 개인 상담 이력은 서로 직접 노출하지 않음
• 양측이 동시에 존재하는 것이 서비스의 장점이므로, 두 앱처럼 완전히 갈라놓기보다 하나의 플랫폼 안에서 역할 토글/권한

5-3. 문서 업로드 허브
• 목적: 계약서/명세서/기타 증빙을 업로드하고 처리 상태를 관리
• 핵심 블록: 문서 유형 탭, 업로드/촬영, 최근 업로드 이력, 처리 상태 배지, 보안 안내
• 고용주 포인트: 여러 건 업로드와 상태 관리가 필요하므로 리스트/필터/일괄 관리에 강해야 함

5-4. 문서 분석 상세
• 목적: 원문, 추출 결과, 위험 포인트, 근거, 다음 행동을 한 화면에서 연결
• 권장 레이아웃: 데스크톱은 원문/추출/리스크 3분할, 모바일은 요약 카드 + 탭 구조
• 고용주 포인트: 수정 대상, 누락 조항, 리스크 우선순위, 체크리스트 연결 버튼이 중심
• 근로자 포인트: 쉬운 언어 요약, 내 권리 관점 설명, 이해 안 되는 항목에 대한 상담 진입이 중심
• 디자인 메모: confidence 와 근거 위치를 보조 정보로 두되, 시각적 중심은 행동 카드에 둔다
5-5. 공식 체크리스트 워크스페이스
• 목적: 고용노동부 공식 체크리스트 문항은 그대로 유지하되, 문서와 상태를 연결해서 해석
• 핵심 블록: 공식 문항, 진행률, 현재 케이스와의 연결 설명, 관련 증빙, 미완료 요약, 다음 단계
• 고용주 포인트: 어떤 문항이 아직 미충족인지, 어떤 서류가 필요한지 바로 확인 가능해야 함
• 근로자 포인트: 문항 자체보다도 왜 중요한지, 내 문서와 어떤 관계가 있는지 쉽게 설명되어야 함
• 디자인 메모: 좌측 공식 문항 / 우측 AI 해설 패널 구조가 가장 설명력이 좋음
5-6. 상담 / 케이스 코파일럿
• 목적: 자유 질의응답이지만 항상 현재 케이스를 바탕으로 답하는 상담 화면
• 핵심 블록: 현재 참조 케이스 배지, 추천 질문, 답변 카드, 관련 문서/법령/체크리스트 링크
• 고용주 포인트: '왜 문제인가'보다 '무엇을 먼저 수정해야 하는가'에 가까운 답변 흐름
• 근로자 포인트: 전문 용어 없이 쉬운 설명, 다음 행동, 기관 연결 안내가 우선
• 디자인 메모: 말풍선보다 카드형 답변이 더 적합하며, 답변 하단 CTA 가 중요
5-7. 기관/교육 추천

• 디자인 메모: '왜 이 추천이 떴는지'를 설명하는 추천 이유 배지가 꼭 필요
